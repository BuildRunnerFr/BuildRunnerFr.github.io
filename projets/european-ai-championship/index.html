Ces scores viennent du classement public, calculé sur une partie des tests. Le classement final utilise une partie cachée.

1 · Localiser un tatouage invisible

Le problème. Une image porte un tatouage invisible (PixelSeal, TrustMark ou StegaStamp) sur une partie seulement de sa surface. Il faut rendre une carte de 128 × 128 cases qui dit où il se trouve. Le score est un mIoU. On dispose de 170 images d'exemple par méthode.

L'idée. Fabriquer nous-mêmes les exemples. Les organisateurs fournissent l'outil qui pose le tatouage : si c'est nous qui tatouons une zone, nous connaissons la réponse exacte, autant de fois que nécessaire.

2 · Reconnaître le modèle derrière une API

Le problème. Trente-trois points d'accès anonymes, cent réponses autorisées pour chacun. Il faut dire lesquels servent le même modèle. Le piège : un déguisement (consigne cachée, persona, tatouage du texte, température) garde le même modèle mais change beaucoup le texte, alors qu'une quantification ou un réentraînement léger change le modèle mais presque pas le texte. Comparer les réponses ne suffit donc pas.

L'idée. Ne pas demander « qui se ressemble ? » mais « qui porte une preuve de déguisement ? ». Et comme les modèles candidats sont ouverts, mesurer exactement à quel point chacun aurait pu écrire une réponse.

ÉtapeScore public
Familles par vraisemblance, variantes par test statistique0,40
Preuves de déguisement : réponses identiques, mots rares, fausse identité0,70

La limite. La base n'est identifiée que pour une famille sur trois. Deux candidats sont restés indiscernables du modèle de base avec cent réponses chacun : un réentraînement très léger est invisible à ce budget.

Où lire. analyse/decision.py et analyse/temperature.py : familles et test de vraisemblance · solution_finale/v80/NOTES.md : la dernière matinée, test par test.

3 · Faire oublier des images à un modèle

Le problème. Un classifieur d'images (ViT-B/16, 100 classes) doit oublier 3 500 images d'entraînement. Le juge est un modèle réentraîné sans elles : il faut lui ressembler image par image, sans le posséder, sans les autres images d'entraînement et sans les étiquettes. Le score vaut zéro si le modèle perd trop en précision.

L'idée. Oublier, ce n'est pas tout rater. Un élève qui a appris des corrigés par cœur doit, pour faire comme s'il ne les avait jamais vus, hésiter là où un autre élève hésiterait.

Où lire. JOURNAL.md : la démarche, version après version · versions/v47/ : la recette en deux étapes · versions/v70/NOTES.md : les derniers réglages.

Ce qu'on retient

  • Quand on a l'outil officiel entre les mains, on peut fabriquer ses propres données d'entraînement.
  • Quand les modèles sont ouverts, on peut tester exactement, et connaître la limite du test.
  • Avant d'optimiser, comprendre ce que la métrique récompense.

Ce qui n'est pas ici

Les poids, les données, les réponses des API et les journaux d'exécution sont restés sur le cluster. Les chemins et identifiants du cluster sont anonymisés dans les scripts : il faut les rétablir pour les relancer.
